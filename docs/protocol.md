# 串口协议（草案，M5 实现）

Pico 通过 USB 同时提供两个通道：

| 通道 | 方向 | 内容 |
|---|---|---|
| USB HID 手柄 | Pico → 电脑 | 摇杆和按键。网页用 Gamepad API 读，不经过这个协议 |
| USB 串口（`usb_cdc.data`） | 双向 | 游戏事件和反馈指令，就是本文档 |

串口里其实有两个口：`console`（REPL 和 `print` 输出）和 `data`（这个协议）。网页连的是 `data` 口，所以调试打印不会和协议混在一起。

## 格式

- 一行一条，UTF-8 文本，以 `\n` 结尾（收到 `\r` 忽略）
- 第一个字符是命令，后面空格分隔参数
- 一行最长 64 字节，超长的整行丢掉并回 `ERR too_long`
- 波特率随便填（USB 串口不看波特率），网页里写 115200

## 电脑 → Pico

| 命令 | 例子 | 作用 |
|---|---|---|
| `?` | `?` | 握手，Pico 回 `HELLO pico-pad <版本>` |
| `V <ms>` | `V 200` | 震动 ms 毫秒（0 = 立即停，最大 2000） |
| `L <n>` | `L 3` | 命数灯显示 n（0–3） |
| `S <n>` | `S 1250` | OLED 显示分数 |
| `T <text>` | `T GAME OVER` | OLED 显示一行文字（最多 16 个字符） |
| `B <name>` | `B miss` | 蜂鸣器音效：`hit`、`miss`、`start`、`over` |
| `R` | `R` | 全部复位：停震动、灭灯、清屏 |

## Pico → 电脑

| 回复 | 什么时候 |
|---|---|
| `HELLO pico-pad 0.1.0` | 收到 `?` |
| `OK` | 命令执行了（游戏里可以不等它） |
| `ERR <原因>` | 命令不认识、参数不对、行太长 |

## 实现要点

- Pico 端：每次主循环用 `usb_cdc.data.in_waiting` 看有没有数据，有才读，凑满一行再处理。不能用阻塞读，否则手柄输入会卡住。
- 震动、音效都记"结束时间"，在主循环里到时间就关，不用 `time.sleep`。
- 网页端：Web Serial 只能在用户点击之后调用 `navigator.serial.requestPort()`，而且页面要是 https 或 localhost。
- 网页断开或刷新时发一次 `R`，免得马达一直震。
